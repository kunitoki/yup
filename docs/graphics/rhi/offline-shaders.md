# Offline Shader Compilation

The [pipeline compilation](pipelines.md) entry points can transpile GLSL at
runtime (`compileFromGlsl`, gated behind `YUP_ENABLE_SHADER_TRANSPILER`), but for
shipping applications you usually want shaders **compiled ahead of time**. YUP
does this with the `yup_shader_bundler` tool, which turns a shader stage set into
a portable `.ysl` **shader bundle** containing every backend's native source plus
reflection data. At runtime you load the bundle and hand it to
[`GpuPipeline::compileFromBundle`](pipelines.md#1-from-a-shader-bundle-recommended) -
no transpiler needed in the final binary.

```{note}
A `.ysl` bundle stores one variant per `(stage × target language)`: WGSL, GLSL,
ESSL, HLSL, and MSL, plus the SPIR-V and the mandatory binding-map reflection.
`compileFromBundle` picks the variant matching the active graphics API.

WGSL variants are produced via a direct GLSL→WGSL transpiler - no SPIRV-Cross WGSL
backend is needed. Reflection data still originates from SPIR-V so binding numbers
match across all targets.
```

## The `yup_add_shader_bundle` CMake helper

The easiest path is the `yup_add_shader_bundle()` function. It builds the
`yup_shader_bundler` host tool once, runs it **at configure time** to produce the
`.ysl`, and embeds the result into a linkable `OBJECT` library via
[`yup_add_embedded_binary_resources`](../../build-system/cmake-api.md#yup_add_embedded_binary_resources).
Because the tool is built in its own host binary tree, this works even when the
outer build is cross-compiling (Android, iOS, WebAssembly).

```cmake
yup_add_shader_bundle(<library_name>
    VERT           <path to .vert file>
    FRAG           <path to .frag file>
    [OUTPUT_NAME   <basename>]      # default: <library_name>
    [RESOURCE_NAME <symbol>]        # default: <library_name>
    [NAMESPACE     <namespace>]     # default: yup
    [ENTRY         <entry point>]   # default: main
    [GLSL_VERSION  <version>]       # default: 450
    [OPTIONS       <flag>...])      # extra flags forwarded to yup_shader_bundler
```

| Argument | Default | Description |
|---|---|---|
| `<library_name>` | *(required)* | Name of the generated `OBJECT` library (first positional argument). |
| `VERT` | *(required)* | Path to the vertex shader source. |
| `FRAG` | *(required)* | Path to the fragment shader source. |
| `OUTPUT_NAME` | `<library_name>` | Base name for the `.ysl` bundle and generated header. |
| `RESOURCE_NAME` | `<library_name>` | Symbol base name of the embedded byte array. |
| `NAMESPACE` | `yup` | C++ namespace wrapping the generated symbols. |
| `ENTRY` | `main` | Shader entry-point name. |
| `GLSL_VERSION` | `450` | GLSL version passed to the compiler. |
| `OPTIONS` | - | Extra flags forwarded verbatim to `yup_shader_bundler` (see [below](#the-yup_shader_bundler-tool)). |

### Example

```cmake
yup_add_shader_bundle(
    "${target_name}_binary_shaders"
    VERT ${CMAKE_CURRENT_LIST_DIR}/data/shaders/cube.vert
    FRAG ${CMAKE_CURRENT_LIST_DIR}/data/shaders/cube.frag
    NAMESPACE   yup
    OUTPUT_NAME ShaderBundle
    RESOURCE_NAME ShaderBundleFile)

yup_standalone_app(
    # ...
    MODULES
        yup::yup_graphics
        yup::yup_shading
        "${target_name}_binary_shaders")   # << link the embedded bundle
```

This emits a header (`ShaderBundle.h`) declaring the embedded bytes:

```cpp
extern const uint8_t     ShaderBundleFile_data[];
extern const std::size_t ShaderBundleFile_size;
```

## Loading and compiling at runtime

Deserialize the embedded bytes into a `ShaderBundle`, then compile a pipeline
from it:

```cpp
#include <ShaderBundle.h>   // generated by yup_add_shader_bundle

auto bundleResult = yup::ShaderBundle::loadFromData (yup::ShaderBundleFile_data,
                                                     yup::ShaderBundleFile_size);
if (! bundleResult.wasOk())
{
    DBG (bundleResult.getErrorMessage());
    return;
}

auto bundle = bundleResult.getValue();

yup::GpuPipelineOptions options;
// ... configure vertex layout / culling / depth-stencil ...

auto pipelineResult = yup::GpuPipeline::compileFromBundle (ctx, bundle, options);
if (pipelineResult.wasOk())
    pipeline = pipelineResult.getValue();
else
    DBG (pipelineResult.getErrorMessage());
```

`ShaderBundle` can also be loaded from a stream, a file, or a `MemoryBlock`
(`loadFromStream`, `loadFromFile`, `loadFromMemoryBlock`) when the bundle is not
embedded.

For repeated compilation across frames or many pipelines, cache the results with
[`GpuPipelineCache`](pipelines.md#gpupipelinecache), which also accepts a
`ShaderBundle`.

## The `yup_shader_bundler` tool

`yup_add_shader_bundle` drives the `yup_shader_bundler` console tool. You can also
invoke it directly to build `.ysl` bundles in a custom pipeline, or to inspect an
existing bundle. The `OPTIONS` argument of the CMake helper forwards any of these
flags verbatim.

### Compile mode

```text
--stage <stage> <path>   Pipeline stage and source file (repeatable)
                         Stages: vertex, fragment, compute, geometry,
                         tesscontrol, tesseval
--vert <path>            Shorthand for --stage vertex <path>
--frag <path>            Shorthand for --stage fragment <path>
--output <path>          Output .ysl bundle file path
```

### Source options

```text
--source-lang <lang>     Source language: glsl, hlsl, essl (default: glsl)
--target-langs <list>    Comma-separated target languages
                         (default: glsl,essl,hlsl,msl,spirv,wgsl)
--entry <name>           Entry point name (default: main)
```

### Compilation options

```text
--glsl-version <n>       GLSL version (default: 450)
--es                     Emit OpenGL ES-style GLSL
--hlsl-model <n>         HLSL shader model (e.g. 50, 60; default: 50)
-DNAME[=VALUE]           Preprocessor define (repeatable)
-I<dir>                  Include search directory (repeatable)
```

### SPIR-V options

```text
--spirv-opt <mode>       Optimization: none, size, perf (default: none)
--spirv-validate         Run SPIR-V validation after compilation
--spirv-debug            Emit debug info in SPIR-V binary
```

### MSL options

```text
--msl-fbfetch            Enable framebuffer fetch for subpass inputs
--flip-vert-y            Flip vertex Y coordinate
```

### Inspect mode

```text
--inspect <path>         Inspect an existing .ysl bundle file
--print <lang>           Print shader source for a language
                         (glsl, essl, hlsl, msl, spirv, wgsl, all; repeatable)
--stage <stage>          Filter by pipeline stage (repeatable; default: all)
--list                   List all variants with source lengths
--info                   Print reflection data for matched variants
```

### Direct invocation examples

```bash
# Compile a vertex/fragment pair into a bundle, optimising for performance
yup_shader_bundler \
    --vert cube.vert --frag cube.frag \
    --output ShaderBundle.ysl \
    --spirv-opt perf

# Only emit Metal and HLSL variants, with a preprocessor define and include dir
yup_shader_bundler \
    --vert cube.vert --frag cube.frag \
    --output ShaderBundle.ysl \
    --target-langs msl,hlsl \
    -DMAX_LIGHTS=8 -I./shaders/include

# Inspect a built bundle: list variants and print the generated MSL
yup_shader_bundler --inspect ShaderBundle.ysl --list
yup_shader_bundler --inspect ShaderBundle.ysl --stage fragment --print msl
```

Forwarded through the CMake helper, the same flags look like:

```cmake
yup_add_shader_bundle(my_shaders
    VERT cube.vert
    FRAG cube.frag
    OPTIONS --spirv-opt perf --target-langs msl,hlsl -DMAX_LIGHTS=8 -I${CMAKE_SOURCE_DIR}/shaders/include)
```

## Choosing an approach

| Approach | When to use |
|---|---|
| `yup_add_shader_bundle` + `compileFromBundle` | **Recommended for shipping.** No transpiler in the final binary; cross-compile friendly; deterministic builds. |
| `compileFromBundle` with a hand-built `.ysl` | Custom asset pipelines, or loading bundles from disk at runtime. |
| `compileFromGlsl` | Live shader editing / prototyping. Requires `YUP_ENABLE_SHADER_TRANSPILER`. |
